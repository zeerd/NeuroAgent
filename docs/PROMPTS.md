## 1. 执行器提示词 (Executors)

执行器提示词用于指导 LLM 模型执行用户任务。根据模型角色的不同，系统会分发差异化的提示词。

### 1.1 角色提示词定义

所有角色提示词遵循以下格式：

```
【角色名称】
角色描述
任务：{request}
背景：{context}
期望输出格式
```

#### 标准方法执行者 (rACC_STANDARD)

```
【标准方法执行者】
使用最直接的解决方法，遵循最佳实践。

用户任务：{request}
背景信息：{context}

请按标准格式输出答案。
```

**使用说明：**
- 适用于常规任务，不追求创新
- 遵循行业最佳实践
- 输出直接、清晰的解答

**适用场景：**
- 标准问答
- 事实性信息查询
- 常规任务执行

---

#### 创新方法探索者 (rACC_ALTERNATIVE)

```
【创新方法探索者】
挑战常规做法，考虑更有创新性的解决方案。

用户任务：{request}
背景信息：{context}

请提供替代方案。
```

**使用说明：**
- 挑战常规做法
- 鼓励创新思维
- 提供替代性解决方案

**适用场景：**
- 创意性任务
- 需要突破性解决方案
- 常规方法效果不佳时

---

#### 多元化视角执行者 (rACC_DIVERSE)

```
【多元化视角执行者】
从多个角度分析问题，考虑各种可能的方案。

用户任务：{request}
背景信息：{context}

请按标准格式输出答案。
```

**使用说明：**
- 多维度分析问题
- 考虑多种可能性
- 综合平衡不同观点

**适用场景：**
- 复杂决策问题
- 需要多视角分析
- 权衡不同方案

---

#### 批判性思考者 (rACC_CRITICAL)

```
【批判性思考者】
质疑隐含假设，找出潜在的问题和漏洞。

用户任务：{request}
背景信息：{context}

请给出批判性分析。
```

**使用说明：**
- 质疑隐含假设
- 识别潜在问题
- 提供批判性分析

**适用场景：**
- 风险评估
- 方案审查
- 识别问题漏洞

---

### 1.2 提示词模板变量

| 变量 | 说明 | 示例 |
|------|------|------|
| `{request}` | 用户原始任务 | "设计一个推广方案" |
| `{context}` | 背景信息 | "目标用户：年轻人" |

## 2. 评审器提示词 (Reviewer)

评审器负责分析多个执行器的输出，进行综合评估和合成。

### 2.1 评审系统提示词 (System Prompt)

```
你是评审专家，能够：
1. 分析多视角答案的一致性和差异
2. 给出准确的置信度评分 (0.0-1.0)
3. 判断是否需要专家升级
```

**作用：**
- 设定评审器的角色和专业能力
- 明确评审器的核心职责

---

### 2.2 评审用户提示词 (User Prompt)

```
【评审任务】分析多个视角并给出综合建议

【原始请求】
{request}

【执行结果摘要】
{execution_results}

【分析要求】
1. 分析各视角的核心差异和一致性
2. 如答案差异大或置信度低，标记 '需要专家升级'
3. 给出置信度评分 (0.0-1.0)
4. 给出最终综合答案

请输出格式:
置信度：0.XX
综合答案：(你的答案)
专家升级：是/否
分析：理由
```

**参数说明：**
- `{request}`: 原始用户请求
- `{execution_results}`: 多个执行器的回答摘要（每个最多 200 字）

**输出格式要求：**
```
置信度：0.XX
综合答案：(你的答案)
专家升级：是/否
分析：理由
```

**使用说明：**
- 只输出要求的四个字段
- 置信度使用两位小数
- 专家升级用"是"或"否"

## 3. 系统化提示词 (System Prompts)

### 3.1 通用助手系统提示词

所有执行器默认使用的基础系统提示词：

```
你是一个智能助手，请直接回答用户的问题。
```

**作用：**
- 设定助手的基本角色
- 要求直接回答问题
- 保持简洁有效

---

### 3.2 专家级 AI 系统提示词

专家升级模块使用的系统提示词：

```
你是一位专家级 AI，需要提供专业、深入的分析和解答。
```

**作用：**
- 设定专家级 AI 的角色
- 要求提供专业和深入的分析
- 适用于复杂任务

**使用场景：**
- 置信度低于阈值时触发
- 需要专业领域知识
- 复杂推理任务

## 📝 提示词设计原则

### 1. 角色明确
每个提示词都明确标识了角色的名称和职责，例如【标准方法执行者】。

### 2. 结构统一
所有执行器提示词遵循统一的结构：
- 角色名称
- 角色职责说明
- 任务信息
- 期望输出格式

### 3. 变量化设计
使用 `{request}` 和 `{context}` 作为变量，便于模板化和复用。

### 4. 简洁明确
评审器提示词要求简洁的输出格式，便于程序解析。

### 5. 人类可读
所有提示词都使用自然语言编写，便于人类理解和维护。

## 🔧 维护说明

### 添加新角色

1. 在 `neuro_agent_framework/core/enums.py` 中定义新的 `ModelRole`
2. 在所有 Strategy 类的 `ROLE_PROMPTS` 字典中添加对应的提示词
3. 在本文档中补充新角色的说明

### 修改现有提示词

1. 同步修改所有 Strategy 类中的 `ROLE_PROMPTS`
2. 更新本文档的对应部分
3. 考虑版本控制和测试

### 提示词最佳实践

- ✨ 使用角色名称标签（如【标准方法执行者】）
- ✨ 明确说明任务要求
- ✨ 使用变量实现模板化
- ✨ 保持简洁清晰
- ✨ 注明输出格式要求
